## 5. Stop rules (implemented in the notebook)
- **NaN** -> `nan_stop`: stop, send logs. No retry.
- **OOM**: one automatic retry with per-device 2 x accumulation 16 (same effective 64); a second OOM -> stop, report. Peak reserved in the speed test was 12.1/15 GB.
- **Stall** (no log output 15 min) -> process killed; NCCL pre-flight failure -> 1-GPU fallback (accumulation x2; ~2x slower, then the plan needs ~4 sessions: report before continuing).
- **Session end** (`needs_resume`): mid eval of the newest checkpoint -> `results/stage2_full_C_mid_step{N}.json`, summary `results/stage2_full_summary_s{K}.json`. The Handler starts the next session with the output attached (section 3); Srimon only needs to know if it was not the planned S2.
- Data cell asserts (stops before training): no disabled/eval sources, rows >= needed, dedicated procedural rows = 0, semantic rows exactly the 2 workflows = 3,000, procedural share 3.5-6.5 %, train texts that equal a val text <= 1 % of val (v7: expected 0). In S2 the data restored from S1 must match `results/stage2_full_data_md5.json`, otherwise stop.
- **Handler check (not automated):** stop and report if eval_loss at step >= 3,000 is above pilot C's final val loss by > 0.05, or s/step > 2.9 (session plan no longer holds).
